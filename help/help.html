觅图采集器 Mito Collector

截图与网页图片采集，直接写入局域网共享文件夹

装好了，两步开始用

  1. 打开设置页 → 保存位置选「WebDAV 直传」，填上 NAS 账号密码，点「测试连接」看到绿灯（第 1 节）；
  2. 在任意网页的图片上点右键 →「将图片保存至觅图」，这张图就存好了。
WebDAV 不需要部署任何东西 —— NAS 自带的 WebDAV 服务就是接收端。若环境里没有 WebDAV，也可以改用「浏览器目录授权」。

1两种落盘方式

浏览器扩展无法直接往任意磁盘路径写文件，所以要在下面两种里选一种。设置页右上角「测试连接」会做真实探测。

WebDAV 直传 推荐 · 零部署

什么都不用装。群晖 / 威联通这类 NAS 大多自带 WebDAV 服务，装上它就等于有了现成的接收端。

目标地址   http://192.168.31.206:5005/Works/PicStorage/clips
NAS 账号   你的群晖 DSM 用户名
NAS 密码   只存在本机浏览器里
  • 群晖端口：5005 走 HTTP，5006 走 HTTPS。用 5006 的话自签证书会让浏览器直接拒绝连接，除非证书已被信任
  • DSM →「套件中心」确认已安装 WebDAV Server；「控制面板 → 用户 → 应用程序」里允许该账号使用 WebDAV
  • 建议单独建一个账号，只给目标共享文件夹的权限，别用管理员
  • 地址末尾就是最终目录，日期子目录由设置页的「文件组织」模板追加
扩展会逐级 MKCOL 自动建目录，并用条件请求保护同名文件 —— 同名不会被静默覆盖，而是自动加 -1、-2。

浏览器目录授权 零部署 · 依赖内核

在设置页点「选择目录…」授权一个目录即可，可以是映射过的网络驱动器。 Windows 上本机 Z: 正好映射到 \\192.168.31.206\Works，所以选 Z:\PicStorage\clips 与上面的 WebDAV 是同一个落点； macOS 上先在访达里 Cmd+K 挂载 smb://192.168.31.206/Works，再选 /Volumes/Works/PicStorage/clips。

这条依赖 File System Access API。部分国产内核阉割了该能力，且 Chromium 对网络驱动器的支持历来不稳，所以作为备用而非首选。

2配置扩展

右键扩展图标 →「选项」，或点面板里的「设置」。

方式 A：WebDAV 直传 推荐

  • 目标地址：写到文件夹为止，例如 http://192.168.31.206:5005/Works/PicStorage/clips
  • NAS 账号 / 密码：群晖 DSM 账号；不填的话无法写入
填完点右上角「测试连接」，它会真的往目标目录写一个文件再删掉。绿灯说明连接、鉴权、写入都通了。

方式 B：浏览器目录授权 零部署 · 依赖内核

  • 先在「此电脑」里把网络共享映射成盘符，例如 Z:\（本机 Z: 已是 \\192.168.31.206\Works）
  • 设置页点「选择目录…」，选中 Z:\PicStorage\clips
  • 浏览器询问权限时选「允许每次访问」，否则重启浏览器后需要重新授权
依赖浏览器的 File System Access 接口。部分国产内核阉割了该能力，在网络驱动器上也可能失败，遇到问题请用方式 A。

文件组织

用模板控制存到哪个子目录、文件名长什么样：

占位符含义
{yyyy} {mm} {dd}年 / 月 / 日
{hh} {mi} {ss}时 / 分 / 秒
{page}网页标题（已清掉非法字符）
{host}网站域名
{type}region / viewport / fullpage / batch / single / video
{n}递增序号
{w} {h}图片宽高
{rnd}随机串

默认是 {yyyy}-{mm}-{dd}/{hh}{mi}{ss}-{page}-{n}.png，按天分目录，一眼能看出是什么时候从哪采的。

什么时候存进子文件夹，什么时候不存？

只看「子目录模板」这一栏，跟别的都无关。最终路径永远是这个式子：

目标目录 + 子目录模板渲染结果 + / + 文件名模板渲染结果

子目录模板结果
填了内容（默认 {yyyy}-{mm}-{dd}）存进子文件夹：clips/2026-10-10/143208-设计参考-1.png
留空不建子文件夹：clips/143208-设计参考-1.png
  • 与采集入口无关：右键剪藏单图、区域 / 可视区 / 整页截图、批量采集、视频封面 —— 走的是同一套规则，落在同一个地方
  • 与网站、图片数量、文件格式无关，不会出现「有的进文件夹、有的不进」
  • 子目录不用手工建：WebDAV 会逐级 MKCOL，目录授权会逐级创建；已存在也算成功
  • 文件名模板只决定文件名，不影响目录层级（把 {page} 写进文件名模板不会多出文件夹）
  • 把 {page} / {host} 写进子目录模板才会按页面 / 站点分文件夹，例如 {host} → clips/example.com/…
  • 设置页「文件组织」下方有一行预览，显示的就是当前模板算出来的相对路径，改完模板立刻能看到
  • 留空后在 NAS 上看着「没进文件夹」，是因为文件真的直接落在目标目录（Works/PicStorage/clips）里了，不是丢到了别处

4复制原图 · 素材工作台 · 反推提示词

复制原图 v1.6.0

点扩展图标 →「复制原图」，把本页最大的那张图以原始文件写进系统剪贴板， 可以直接粘进 PS / Figma / 微信。 面板会回报真实像素与体积（例如「已复制 2400×1600 · 2.4 MB」）—— 这是分辨「拿到的是原图还是页面缩略图」最快的办法。

浏览器自带的右键「复制图片」复制的是页面上渲染的那一张：站点普遍把缩略图放在 src、把大图藏在 srcset 或 data-orig-img 里（Pinterest 最典型， src 全是 236x），所以浏览器那条路复制出来往往只有几百像素。 本扩展走的是与剪藏相同的「大图推断」：能按 CDN 规则逆推原图就取原图，取不到才退回页面版本， 并在提示里说明「原图不可达」。

素材工作台 扫描当前目录

点扩展图标 →「素材工作台」，它只扫描当前配置的那个目录 （WebDAV 目标地址，或已授权的本地目录），不递归、不越界：

  • 进来先列目标目录这一层，点文件夹才往下一层走；顶部面包屑随时回上级
  • 缩略图按需加载（长边 460px），大目录不会一次性把几 GB 原图读进内存
  • 选中任意一张：可复制图片、反推提示词、打开原图
  • 右上角显示本地 ComfyUI 是否在线，点它可以重新检测
反推的入口不在右键菜单里（右键菜单只保留一项剪藏，见上一节）。路径固定是： 点扩展图标 →「素材工作台」→ 点一张图 → 右侧面板「反推提示词」。 没选中图片时右侧也会写着这三件事，不用先猜 —— 那里同时显示当前目录有几张图、ComfyUI 在不在线。

反推提示词 本地 ComfyUI

在工作台里选中一张图 →「反推提示词」，本机的 Qwen3-VL 4B（Krea 2 的文本编码器） 会按 Krea 2 Turbo 的写法生成一段可直接使用的英文提示词：

  1. 顺序是「主体与姿态 → 外观材质 → 构图与镜头 → 环境 → 光线色彩 → 整体风格」，一到两段自然语言，不堆关键词
  2. 结果出现在右侧文本框，可改、可一键复制；生成时会显示已等待秒数与 ComfyUI 队列长度
  3. 指令模板可以在设置页 → 反推提示词里整段改写，留空则用内置的 Krea 2 结构
前置条件：本机 ComfyUI 已启动（默认 http://127.0.0.1:8188），并且 models/text_encoders/ 里有 qwen3vl_4b_fp8_scaled.safetensors。 工作流只用 ComfyUI 原生节点（LoadImage → CLIPLoader → TextGenerate → PreviewAny）， 不需要安装任何第三方节点包。设置页的「测试 ComfyUI」会告诉你连没连上。
反推和出图共用同一个 ComfyUI 队列，正在跑图时会排队 —— 界面会显示「队列：运行 N / 等待 M」，不是卡死。
如果你的 ComfyUI 是旧版、又恰好填的是 127.0.0.1，可能看到「上传图片失败（HTTP 403）」： ComfyUI 有一道防护，只接受与自己同源的 POST，而扩展的请求来自 chrome-extension://。 本扩展会自动改写这两个请求头（declarativeNetRequest），正常不需要你做什么； 万一仍然 403，把地址换成局域网地址（例如 http://10.222.222.1:8188）通常立刻可用， 或者在 ComfyUI 启动参数里加 --enable-cors-header "*" 后重启。

用另一台电脑的 ComfyUI v1.6.1

地址不是只能填本机：设置页 → 反推提示词 →「ComfyUI 地址」里可以填任何一台机器的地址。 典型场景是在家里用 MacBook，调单位那台机器的显卡。要跑通，需要四件事同时成立：

  1. 对方 ComfyUI 要允许外部访问。它默认只监听 127.0.0.1，别的机器一律进不来。 启动时加 --listen 0.0.0.0（绘世启动器里是「允许局域网访问」那个开关），重启后生效。
  2. 地址写对。可以只填 IP，端口默认 8188： 172.18.23.232 与 http://172.18.23.232:8188 等价。 同一局域网填内网地址；跨网（家里 → 单位）要填隧道里那台的地址。
  3. 防火墙放行 8188（Windows 第一次启动 ComfyUI 时那个弹窗要点「允许」）。
  4. 两台机器之间要有网。不在同一个局域网时，先连上组网工具（节点小宝 / Tailscale 这类）， 再用它分配的地址。直连公网 IP + 端口映射通常不可行，别在这上面耗时间。
设置页的「常用位置」就是为了两地来回切：填好地址点「存为常用」，以后在下拉里选一下即可， 选中会立刻测一次连通性。地址会自动规范化（补 http://、补默认端口、去掉尾部斜杠）。
连不上时，报错会按「本机 / 远程」给两套不同的排查建议 —— 远程那套直接列出上面这四条，不用自己猜。
跨网别忘了上传体积：一张 4K 原图十几 MB，家里上行传它会等到怀疑人生。 设置页有「上传前压到长边」，填 1536 就够视觉模型看了，体积通常只剩十分之一； 反推完成后状态栏会写清楚「上传 1536×1024 · 312 KB（压缩自 8.4 MB）」，压没压、压到多少一目了然。 填 0 就是不压（本机用时建议保持 0）。

5常见问题

连接失败 / 上传超时

WebDAV（方式 A）：

  • 报「账号或密码不正确」：核对 DSM 账号密码；注意这是 NAS 登录密码，不是 SMB 里另设的共享密码
  • 报「该账号没有此目录的 WebDAV 权限」：DSM →「控制面板 → 用户 → 应用程序」里勾上 WebDAV
  • 报「路径不存在」：地址里的共享文件夹名写错了。群晖的 WebDAV 路径是 /共享名/子目录，区分大小写
  • 报「无法连接」：确认端口（群晖 5005 / 5006）与网络可通

右键菜单里只有一项，找不到区域截图

这是刻意的。右键菜单只保留「将图片保存至觅图」这一个一键动作（与 Billfish 采集扩展一致）—— 同一扩展注册多项时，Chromium 会把它们折叠成一个「觅图采集器 ›」二级菜单，一键剪藏就变成了两次点击。 区域截图 / 可视区截图 / 整页截图 / 批量采集都在扩展面板里，也都有快捷键。

改了菜单名字 / 图标，右键里还是旧的

  • 右键菜单由浏览器进程持有，后台脚本休眠不会让它消失。改了代码后要让后台重新跑一遍才会重建 —— 打开一次扩展面板（点工具栏图标）就会自动重建一次，不必专门跑扩展管理页； 想显式触发就点面板底部那行右边的「重新注册」
  • 不要用「移除」来更新版本：移除扩展会连带删掉它的存储 —— WebDAV 账号密码、 常用位置、各项开关、累计统计全都没了，表现是「突然提示账号未填写」或「保存到默认地址失败」。 更新请用扩展卡片上的 刷新 ↻ 按钮（或本页最下面那段里说的方式）； 只有安装路径变了（换了目录、重新解压到别处）才需要移除重加，那时也请先在 设置页底部点「导出配置」，重装后「导入配置」补回来
  • 点完 ↻ 还要按 F5 刷新页面：已经打开的标签页不会自动换脚本，里面那份的 chrome.runtime 已经断开 —— 表现就是「点保存 / Alt+右键 报错」，而弹窗里连一条失败记录都没有 （因为请求根本没发出去）。v1.7.4 起扩展面板会直接发现这件事：顶部出现黄色警告条写明本页脚本是旧版， 点击面板里的「采集统计」也会显示「上次成功 时间」，刚点过却没变就是同一个原因
  • 确认选中的就是本目录，而不是早先解压在别处的旧副本
  • 自检：把鼠标悬停在工具栏图标上，悬浮提示里带版本号（形如「觅图采集器 1.7.4 · …」）—— 版本号对得上，说明浏览器跑的就是这份代码

卸载 / 删掉别的扩展之后，右键里的这一项不见了

本插件的右键项与其它扩展（例如 Billfish 采集扩展）完全独立，删掉谁都不会连带删掉对方。 但这个菜单项由浏览器进程持有，而 Chromium 在扩展集合发生变化时 （安装 / 卸载 / 禁用任意一个扩展）会重建整张右键菜单 —— 重建那一刻本插件的后台脚本若正在休眠， 这一项就会缺席，直到后台被唤醒才会补回来。看起来就像「删掉 Billfish 之后功能没了」。

  • 当前版本已加兜底：切换一次标签页就会让后台脚本醒来并自动重建菜单
  • 也可以手动唤醒：在扩展管理页点一次「刷新」，或点开一次扩展面板
  • 自检：打开扩展面板，最下面一行会显示「图片右键菜单已就绪」； 若显示未注册，点它右边的「重新注册」即可
  • 另外注意：菜单项只在右键点在图片上时出现（背景图、canvas、视频封面不算），点在空白处或文字上本来就没有它

扩展管理页里出现错误 / 红字

  • 先看版本号对不对：卡片上的版本和工具栏图标悬浮提示里的版本一致，才说明浏览器跑的是这份代码。 错误列表跨版本累积，重载/刷新扩展都不会自动清空它
  • 点错误列表右上角的「全部清除」，再照出问题的操作重新触发一次 —— 清掉后不再出现的就是历史记录，不必管
  • 已知会在这里报错的问题都已修掉：帮助页的内联脚本违反内容安全策略、 批量保存没有标签页时抛异常、以及一批 Promise 形式的浏览器接口调用没接住失败
  • 从 1.5.6 起，后台与自己这两个页面都装了兜底网：万一还有漏网的异步错误， 只会写进开发者控制台（console.warn），不再往错误列表里冒
  • 若清理后仍会重新出现，把那一行展开后的「上下文」与「叠加追踪」反馈过来

右键剪藏报「图片抓取失败」

  • 扩展会先直接抓原图，失败后再回页面里带页面自身的 Cookie / Referer 重试一次。两次都失败才会报错
  • 常见原因是该图需要登录态或已过期的一次性签名地址 —— 刷新页面后重新右键即可
  • 页面内的 blob: 图片会自动改由页面读取，无需额外操作

批量采集有些图没采到

  • 图片是 CDN 带防盗链的，两次尝试都取不到原图。这种会记为「失败」
  • 懒加载图片需要先把页面滚一遍，让它真正加载出来
  • 用「最小边长」过滤掉小图标

整页截图缺一块 / 有重复的导航栏

  • 采集时会自动隐藏 position:fixed / sticky 的元素，若页面用其他方式固定会残留
  • 懒加载很重的页面建议先手动滚一遍到底部，再触发整页截图
  • 页面特别长时可在设置里调整「整页截图最大高度」

同一张图被反复保存

打开设置里的「跳过重复图片」，按内容 SHA-256 判断，重复的直接跳过。想重来可以在设置页点「清空去重记录」。

截图存的是网页图片的原始格式吗？

是。批量采集和单图采集保存的都是原始文件，不做任何重编码。只有截图（区域 / 可视区 / 整页）会按设置里的格式输出。

隐私说明

所有数据只写到你自己配置的目录，不经过任何第三方服务器。扩展需要「读取所有网站数据」的权限用于抓取页面图片和截屏，这是这类工具的必要权限。

WebDAV 模式下，NAS 账号密码只存在本机扩展的存储里，仅在向该 NAS 发请求时用于 Basic 鉴权。写入路径由模板生成且经过清洗，.. 与路径分隔符会被剥离。建议单独建一个只对该共享文件夹有权限的 NAS 账号。

扩展不开任何本地监听端口，也不接受来自网页的连接，因此没有可被外部写入的入口。写入路径由模板生成且经过清洗，.. 与路径分隔符会被剥离。

反推提示词只会把图片发给你自己填的 ComfyUI 地址（默认 127.0.0.1），不经过任何云端服务；生成的提示词只保存在当前页面里，关掉就没了。
